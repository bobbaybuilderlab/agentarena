# Review Playbook

This document describes the engineering review system for this repository, with an explicit focus on malicious attack vectors, loopholes, and trust boundaries.

## Review System (Sustainable, Repeatable)

### Required Reviews

For any change that touches authentication, sockets, room lifecycle, or ops/admin tooling:
- 1 reviewer focused on architecture and correctness (state, concurrency, invariants)
- 1 reviewer focused on security/abuse (threat model, authn/authz, XSS/CSRF, injection)

For release cuts:
- Run `release-gate` workflow
- Update the Risk Register if any new risks are introduced or accepted

### Review Categories (Use as Lenses)

- Architecture: state ownership, persistence boundaries, idempotency, replay safety, invariants
- Security: authn/authz, session lifecycle, token handling, input validation, XSS/CSRF, SSRF
- Abuse/cheating: client trust, rate limiting, game loopholes
- Reliability: timeouts, retries, error handling, observability, backpressure
- Privacy: logs, telemetry, PII, retention

### Threat Model Quick Template

Write this (briefly) in PR descriptions for risky changes:
- Assets: what must be protected (sessions, player identity, room state, ops tools)
- Actors: who can attack (anonymous web users, authenticated players, operators, bots)
- Trust boundaries: browser -> server, sockets, ops pages, connector boundary
- Entry points: HTTP routes, socket events, reconnect/join flows

### Red-Team / Agent-Based Reviews

It is worth running "attacker" agents against the game and APIs as a continuous experiment, but treat it as complementary to deterministic checks:
- Agents are good at finding weird sequences and gameplay loopholes.
- Agents are not a substitute for authz proofs, invariants, or formal gates.

Operationally:
- Keep adversarial prompts/versioning in a dedicated place (not in production code paths).
- Record any exploit sequences discovered and convert them into regression tests.

## CI Gates

We use three workflows:
- `ci-fast`: PR gate; quick deterministic checks
- `release-gate`: heavier gate for tags/manual releases
- `nightly`: scheduled checks; produces artifacts for inspection and catches drift
